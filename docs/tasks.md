# 作業と検証の計画

**未入力のテンプレートです。作業の完了実績ではありません。** 確認済みの[product.md](product.md)と画面設計をCopilotのPlanで読み、会話に計画の草案を出します。チームの確認後、編集できるモードへ切り替え、実装を始める前にこのファイルへ保存します。

## 最初のタスク

mainではアプリ・テスト・CIはまだありません。Planで構成を合意したら、最初に「最小アプリを生成して起動・確認できる状態にする」作業を置きます。必要な依存関係、最初の動作を確かめるテスト、同じ確認を行うCIを用意し、実際のコマンド・ポート・実行環境・環境変数・公開方針を[development.md](development.md)へ記録します。生成しただけでは完了にせず、起動と確認の成功を記録します。Dockerfileや公開用設定は、公開すると決めたときに加えられます。

初心者向けブランチから始めた場合は、準備済みの構成を確認するところから進めます。

## AIへの依頼に含めること

- 必須機能を作り、検証・修正を続けること。
- 仕様や期待結果を都合よく変更しないこと。
- 追加支出・有料契約・秘密情報が必要なら実行前に対象と理由を示すこと。
- [development.md](development.md)の実行・確認方法を使い、コマンドと結果、未達・未確認を[verification.md](verification.md)へ残すこと。
- CIが未作成・未実行なら「未確認」とし、生成や設定だけで成功扱いにしないこと。

最初に選んだ編集・実行場所を記録し、変更したら更新します。環境を切り替える前にこの引き継ぎを更新し、Gitで保存します。次のAIはこの記録・仕様・Gitの変更を読み、記録された実行場所で起動と基本動作を確認してから続きを進めます。Appで編集しCodespacesで実行する場合は、確認手順を案内して学生が返す結果を待ちます。
