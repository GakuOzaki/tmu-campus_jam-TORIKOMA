# 実装して、確かめながら完成へ進める

このリポジトリは汎用の Vite + React + TypeScript とNode.js APIのスターターです。[締切管理の例](../examples/deadline.md)を完成済みのアプリとして含むものではありません。各環境ガイドのPlanで[product.md](../product.md)へ保存した企画・完成条件を使います。未整理の場合は、先に環境ガイドのPlanへ戻って合意・保存します。

このページは[Codespaces](../codespaces.md)と[Copilot app](../copilot-app.md)に共通する進め方です。環境ガイドで終えた起動確認や計画をやり直す必要はありません。

必要な節を読んだら、選んだ環境の実装（[Codespacesの手順5](../codespaces.md#implementation)・[Copilot appの手順5](../copilot-app.md#implementation)）へ戻ります。依頼文・3つの文書・実行コマンドを使う理由は、[Copilotと開発する3つの工夫](ai-development-tips.md)で確認できます。

## 1. 起動と確認の方法をそろえる

Node.js 24 LTSを使います。**選んだ実行場所**のリポジトリのルートで、依存関係をそろえて開発サーバーを起動します。Copilot appで編集してCodespacesで実行する場合は、[AppのGUIで変更を渡す手順](../copilot-app.md#codespacesへ変更を渡して確認する)を使い、次のコマンドはCodespacesのTerminalで実行します。

```bash
npm ci
npm run dev
```

Node.js開発サーバーの4280番を開き、画面が見えることを確かめます。PC・Codespacesでの開き方とAPIの追加は[共通の開発環境](local-development.md)を参照してください。

## 2. Planで作業と検証を決める

CopilotのPlanを使い、企画・画面・既存コードを読ませます。完成条件を作業単位に分け、「作るもの」「対応するDoD」「確かめ方」の草案を会話に出してもらいます。Planではファイルを編集できない場合があります。チームで確認した計画は、実装できるモードへ切り替えてから[tasks.md](../tasks.md)へ保存します。既に保存済みなら、次の実装へ進みます。

```text
目的：
Planで、必須機能を完成させる作業と検証方法の草案を会話に出してください。

文脈：
docs/product.md と画面設計、既存コードを読んでください。

制約：
仕様が未入力なら先に必要な点を確認してください。まだファイルの編集や実装はしないでください。

完成条件：
各作業に対応するDoD、依存する作業、確認方法が示され、未決定の点が分かる草案になっていること。
```

チームは、必須機能の漏れと不要な追加がないかを確認します。小さな文言修正まで毎回新しい計画を作る必要はありません。

## 3. AIに実装・検証・修正を続けてもらう

**各環境ガイドの手順5で実装依頼を送信済みなら、次の依頼文を重ねて送る必要はありません。** 現在の作業・結果を引き継ぎ、下の確認方法を使います。未送信の場合だけ、選んだ実行場所に合う依頼文を使ってください。

編集と実行が同じ場所なら、次を送ります。**Appで編集しCodespacesで実行する場合は、[App手順5の依頼文](../copilot-app.md#5-interactiveで実装と確認を繰り返す)を使います。** この経路では、学生のGUIでのcommit・push、Codespacesでの確認、結果の返却を待ってから修正を続けます。

```text
目的：
合意した計画の未完了タスクから実装し、完成条件を満たすまで検証・修正を進めてください。

文脈：
確認済みの docs/product.md、計画、作業に必要なコードを読んでください。
承認した計画が未保存なら docs/tasks.md へ保存してください。

制約：
仕様を勝手に広げず、追加支出、有料サービスの契約、秘密情報が必要になる作業は実行前に対象と理由を説明してください。
権限不足や同じ不具合で進展がない場合、またはチームが決めた上限に達した場合は、試したことと再開に必要な情報を報告してください。

完成条件：
対応するDoDを確かめるテストを用意し、npm run check と npm run test:e2e、必要な動作確認で実際の結果を確かめてください。
失敗や未達があれば原因を直して再確認し、実行していない確認は未確認としてください。
終了時に変更内容、実行した確認と結果、未達・未確認を docs/verification.md に残してください。
```

以下も、選んだ実行場所で行います。ブラウザテストの初回だけ、次を実行します。Codespacesでは初回の環境準備に含まれています。

```bash
npx playwright install chromium
```

LinuxでOSのライブラリ不足が出た場合は `npx playwright install --with-deps chromium` を使います。

自動確認は次のコマンドです。

```bash
npm run check
npm run test:e2e
```

`check` はlint・型・buildの確認、`test:e2e` はブラウザでの自動確認です。スターターのテストが通っただけでは、自分たちのDoDを満たした証拠になりません。最初の画面用の `tests/starter.spec.ts` を、企画に合う入力・操作・期待結果を確かめるテストへ更新し、必要なケースを追加します。API・画面配信を確かめる `tests/runtime.spec.ts` は残して実行します。

## 4. 完成条件に戻って確認する

AIの完了報告を、[検証の進め方](verification.md)で確かめます。別の学生が必須DoDに対応する主要な操作経路を実際に試し、未達なら修正へ戻します。

仕様を変えたら、まず `product.md` の機能・DoD・除外範囲と画面設計を更新し、`tasks.md` とテストもそろえます。会話だけで仕様を変更しないでください。

同じ失敗を繰り返したら、[改善する場所の選び方](ai-development-tips.md#同じ失敗を繰り返したら何を直すか)を使い、依頼・資料・テスト・環境のどこに原因があるかを確かめます。原因に合う小さな改善を行い、同じ条件で再確認した結果を検証記録へ残します。

セッションや開発環境を切り替える前に、実装済み・未完了、確認結果、次の作業を文書に残してGitで保存します。次のAIは文書とGitの変更を読み、起動・基本動作を確認してから続きを進めます。

実装後は、選んだ環境のチーム確認（[Codespacesの手順6](../codespaces.md#team-verification)・[Copilot appの手順6](../copilot-app.md#team-verification)）へ進みます。必須条件と人の操作確認まで終えている場合は、[Codespacesの手順7](../codespaces.md#save-and-share)・[Copilot appの手順7](../copilot-app.md#save-and-share)で保存・PR・CIの確認を済ませ、[発表・振り返り・終了](presentation.md)へ進みます。
