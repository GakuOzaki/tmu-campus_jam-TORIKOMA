# デモ・発表して、次へ引き継ぐ

使っている環境ガイドの「保存・PR」で、変更・検証記録・CIの結果を共有したら、このページへ進みます。**動くプレビューで発表できます。Azureへの公開は必須ではありません。** 残る未達・未確認は隠さず、どこまで確かめたかを伝えます。

## 1. デモの環境を用意する

[共通の開発環境](local-development.md)に沿って、チームが確認したアプリを起動します。CodespacesのPrivateのプレビューは、ログイン済みの同じPCを投影して見せられます。別の参加者がそのURLを開けるとは限りません。発表が終わるまでサーバーとCodespaceを動かしておきます。

デモはダミーデータで、利用者の最初から最後までの主要操作を一つ通します。接続トラブルに備えて、共有してよいスクリーンショットを残しても構いません。画像で説明した場合は、実演と区別します。

継続して共有できるURLが必要なチームは、ここで[Azure Container Appsへの公開（任意）](publish.md)へ進み、公開URLの確認後にこのページへ戻ります。公開の準備が整っていなくても、確認済みのプレビューで発表できます。

## 2. 企画・動作・確認結果を伝える

新しい仕様書を作り直さず、既に残した記録を使って次の順で説明します。発表時間は当日の運営案内に合わせます。

| 話す順番 | 伝えること | 使う記録 |
| --- | --- | --- |
| 誰の何を解決したいか | 困った場面、選んだ課題、今回の解決策 | [product.md](../product.md)の企画文と根拠 |
| どの操作で役立つか | コア機能を主要な利用フローに沿って実演する | productの画面・遷移、起動したアプリ |
| どこまで確かめたか | 達成した条件、自動確認、別の学生の操作で分かったこと | [verification.md](../verification.md)の結果と証拠 |
| 何が残っているか | 未達・未確認、対象外、次に直すこと | verificationと[tasks.md](../tasks.md) |

「アプリが動いた」と「利用者の困りごとを解決できた」は分けます。利用者への確認がまだなら、その効果は未検証の仮説として説明してください。参考例の数値や発言を、チームが調べた結果として発表しません。

## 3. Copilotとの開発を振り返る

開発中に見た3つの図を使い、自分たちが行った工夫を一つずつ振り返ります。追加の演習や長いレポートは不要です。

- [プロンプトの図](ai-development-tips.md#prompt-engineering)：依頼の目的・制約・完成条件を、どう具体的にしたか。
- [コンテキストの図](ai-development-tips.md#context-engineering)：どの資料を渡し、決定をどのファイルへ残したか。
- [ハーネスの図](ai-development-tips.md#harness-engineering)：何を動かして確かめ、どの結果から修正したか。

次の開発にも使いたい気づきや残る作業は、このあとの手順4で[tasks.md](../tasks.md)の引き継ぎへ残します。

## 4. 発表後に保存して終了する

元のPRをマージ済みで、次の作業ブランチをまだ用意していなければ、記録を編集する前に[マージ後の作業準備](build-loop.md#after-merge)を済ませてこの節へ戻ります。準備済みの作業ブランチや未マージのPRがあれば、それを使います。

1. 発表や操作確認で分かったことをverification、次の作業をtasksへ残します。企画を変えると決めた場合はproductも更新します。
2. 使っている環境の[Codespacesの保存手順](../codespaces.md#save-and-share)／[Copilot appの保存手順](../copilot-app.md#save-and-share)でcommit・pushし、PRと最新CIを確認して記録も共有します。この段階で発表をやり直す必要はありません。
3. [起動・終了の手順](local-development.md)に沿って開発サーバーを終了します。手動で起動したコンテナがある場合は、それも停止します。
4. Codespacesを使ったチームは、[Codespaces一覧](https://github.com/codespaces)の **… → Stop codespace** で停止します。ブラウザタブを閉じただけでは停止したとは判断しません。
5. Azureへ公開したチームだけ、[公開後の利用終了・継続](azure-setup.md#5-利用を終えるとき)を確認し、継続する担当や不要リソースの扱いを決めます。

再開するときは、[保存済みの作業から続ける手順](build-loop.md#resume-work)で、現在の決定・実行場所・最後の確認結果から続けます。
