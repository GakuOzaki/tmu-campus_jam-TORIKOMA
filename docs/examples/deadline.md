# 記入例：締切を近い順に見られるアプリ

**説明用の参考例です。実際の学生調査や実装・検証の実績ではありません。** 数値や発言を自分たちの事実として使わず、本番では各チームの企画に差し替えます。mainにはアプリコードを置いていません。この例を使う場合も、必要な構成をCopilotと選び、最初のタスクで生成します。実装済みの締切アプリが配布されるわけではありません。

## 課題から企画へ

授業の課題、レポート、ES、シフト提出などの困りごとを出し、「締切・提出日を忘れる」にまとめます。頻度、不利益、今の対処を聞いて、取り組む価値を確かめます。

- 事実の**書き方の例**：「聞いた5人中4人が締切を忘れた経験がある」。この数値は架空です。
- 原因の仮説：締切の案内が別々の場所にあり、1か所に集める手間がかかる。
- 問い：どうすれば大学1・2年生が、締切の散らばる状況を解消し、取り組む順番を判断できるか？

クレイジー8では、期限順の一覧、通知、スクリーンショットからの読取、友達との共有などを出します。解決する度、作れる度、ワクワク度で比べ、今回は「期限順の一覧」を選びます。

> 【大学1・2年生】が、【複数の授業の課題が重なるとき】に【締切が別々の場所にあり、取り組む順番が分からないこと】で困っている。そこで【締切を手入力で1つの一覧に集め、近い順に表示すること】で判断を助ける。

手入力の集約でも、登録の手間は残ります。「自動収集できた」「提出忘れを防げた」とは主張しません。その効果は利用者に確かめる仮説です。

## 開発要件

| コア機能 | 利用者にとっての役割 |
| --- | --- |
| 締切を登録する | 別々の場所の締切を1か所に集める |
| 近い順に一覧で見る | 先に取り組むものを判断する |
| 提出済みにする | これから取り組むものに絞る |

利用フローは「締切を入力 → 一覧を見る → 取り組む順番を判断 → 提出済みにする」です。通知、授業サイトからの自動取得、ログイン、共有DBは今回の対象に含めません。デモの保存先はブラウザ内とし、他の端末との共有は行いません。

手書きで「一覧」と「登録」の2画面を描き、Figmaで追加 → 登録 → 保存 → 一覧へ戻る流れと、一覧の提出済み操作をクリック確認してから実装します。

## 技術を選ぶときの例

この範囲なら、ブラウザ内に保存するWebアプリが候補です。素のHTML・CSS・JavaScriptでも、ReactなどのUIライブラリでも実現できます。チームが説明・修正できるか、短時間で検証できるかで選びます。公開先がContainer Appsなら、静的な画面だけでもHTTPサーバーをコンテナに含めます。不要なAPIや共有DBを、教材の都合だけで追加する必要はありません。

選んだ技術と理由、起動・確認方法を[development.md](../development.md)へ残します。

## DoDと受入操作の例

条件は「締切を3件入力すると近い順に並び、提出済みにすると未提出の一覧から消える」です。相対日数を表示する場合、デモの基準日と一致する値で確かめます。

1. 空の状態から、次の3件をこの順で登録します。日付はデモ用の固定値です。

   | 登録順 | 課題 | 締切 |
   | --- | --- | --- |
   | 1 | 英語の小テスト | 2026-10-22 |
   | 2 | 経済学レポート | 2026-10-20 |
   | 3 | 統計学の課題 | 2026-10-21 |

2. 一覧が「経済学 → 統計学 → 英語」の順になることを確認します。
3. 「経済学レポート」を提出済みにし、未提出の一覧から消えることを確認します。
4. 一覧の残りが「統計学 → 英語」で、他の課題が消えていないことを確認します。
5. 保存・戻る・追加など、完成条件に対応する主要な操作経路を別の学生も手動で確かめます。

この操作を自動テストにする場合も、同じ入力と期待結果を使います。ここに記載した手順はまだ実行していません。実際の結果は[verification.md](../verification.md)へ記録します。

例を確認したら、自分たちの[企画づくり](../common/ideation.md)へ戻ります。企画済みなら、[元資料の置き方](../source/README.md)に沿って資料を揃え、[CodespacesのPlan](../codespaces.md#planning)・[Copilot appのPlan](../copilot-app.md#planning)へ進みます。検証中にこの例を参照した場合は、自分たちのDoDの入力・期待結果へ置き換え、[確認の進め方](../common/verification.md)へ戻ります。
